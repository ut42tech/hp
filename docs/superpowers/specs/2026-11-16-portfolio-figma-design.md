## 1. 目的と背景

ポートフォリオサイトの一番の目的は**第一印象**。開いた人にまず楽しんでもらい、UX にこだわりきったサイトを触ることで、本人の技術力とデザインセンスを体感してもらう。説明で伝えるのではなく、サイトそのものが作品になる。

雰囲気は「クリエイターっぽい」「洗練されている」「Figma を連想させる」。スクロールに合わせたアニメーションと、適度な 3D を入れたい（3D は後で考える）。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール

- 「キャンバスの上で、カーソルたちが目の前でサイトを組み上げる」体験が、Figma の画面とプロトタイプで再現されている。
- 色・フォント・角丸などが Figma の変数になっていて、ライト／ダークの2モードを持つ。値は `packages/tokens/tokens.css` にそのまま移せる。
- 実装者が Figma を見るだけで、完成形と組み立ての流れの両方を組める。

### 非ゴール（今回はやらない）

- 3D オブジェクトの造形。置き場所（枠）だけ確保する。
- コードでの実装、`packages/tokens` の値の差し替え。
- 実際の作品・経歴・記事の文章。仮の文章でよい。
- 英語版の画面。日本語で作り、英語を後から足せる余地だけ残す。

### アンチゴール（できても失敗とみなすもの）

- 既存のサイトやテンプレートの**模倣に見える**こと。配色・文言・レイアウトは自前にする。
- Figma そのもののロゴや UI の**模倣**。「デザインツールの手触り」の引用にとどめる。
- 演出のせいで**情報にたどり着けない**こと。急いでいる人（採用担当など）がすぐ中身を見られる道を必ず残す。

## 3. 見た目の方向性

ブレストで検討した見た目の3案（A キャンバス／B エディトリアル／C プレイフル・オブジェクト）からは、**A を土台**にした。C のカラフルな図形は、3D を検討するときの候補として残す。

## 4. アプローチ

| 案 | 内容 | 判断 |
| --- | --- | --- |
| **1. Figma Design で、変数と部品から正式に組む** | 変数（ライト／ダーク）、部品、画面を作る。組み立ての動きは Figma の Motion（タイムラインのキーフレームと文字の打ち込み表現）で作る。 | **採用（Claude の判断。本人は「Figma でかなりの再現性でやってほしい」と依頼）**。動きの再現とコードへの引き継ぎを両立できる。 |
| 2. Figma Make で動く試作を作る | 動きの再現度は高い。 | 不採用。変数や部品が整理された形で残らず、`packages/tokens` に引き継ぎにくい。 |
| 3. 先にコードで作って Figma に取り込む | — | 不採用。「Figma でデザインを決める」という本人の意図と順番が逆になる。 |

## 5. 決まったこと

### 5.1 体験の流れ（本人と合意済み）

1. **開いた瞬間**: 空のキャンバス（ドット方眼）に、役割の名札が付いたカーソルが入ってくる。Design が Hello フレームの枠を描き、ワイヤーの箱を置く。Frontend が名前を打ち込み、モットーやタグが現れる。最後に 3D 担当が図形を置く（形は後で決めるので、今回は枠だけ）。
2. **完成後**: カーソルたちが訪問者のカーソル（「you」）のそばに寄ってくる。
3. **スクロール**: 次のフレームに着くたびに、そのフレームも同じように組み上がる。
4. **近道**: 上部のナビゲーションから各セクションへ直接飛べる。Esc で演出をすべて飛ばせ、再生し直すこともできる。

カーソルの名札は**本人の役割**にする（Design / Frontend / 3D など）。一人で設計から実装まで作れることを、そのまま演出にする。

### 5.2 情報の構成（本人が決定）

トップページは上から次の順に並ぶ。セクションは4つに絞る。

| フレーム | 中身 | 下層ページ |
| --- | --- | --- |
| **Hello** | 名前、モットー（`profile.motto`）、役割タグ（`profile.roleTags`）、所属 | — |
| **About me** | 自己紹介の要約、使っている技術 →「もっと読む」 | About me |
| **Works** | 作品と経歴（インターン・受賞など）を1本の年表にまとめる（本人は「Works(=Experience)」と指定）。トップには新しいものから数件 →「すべて見る」 | Works 一覧、作品の詳細 |
| **Press** | 記事（Zenn / Qiita / note）、動画（YouTube）、登壇、掲載 →「すべて見る」 | Press |

連絡先はセクションにしない（本人の指定）。**フッター**に SNS 7 つ（`profile.social`）と連絡先を置き、**ヘッダー**には Contact へのリンク（フッターへ移動）を置く（Claude の判断。ヘッダーを詰め込まずに、どこからでも連絡先へ行けるようにするため）。

ナビゲーションは About me・Works・Press・Contact とテーマ切り替え。

### 5.3 見た目（Claude の提案。本人が A＋カーソル案のモックアップに「そんな感じ」と返答）

- 背景はグレーのドット方眼のキャンバス。各セクションは白いフレームで、左上に小さくフレーム名が付く。
- 色はグレーと白が基本。鮮やかな色は**カーソルの名札**と（後で入れる）**3D オブジェクト**にだけ使う。
- 組み立ての途中は、選択枠（四隅にハンドル）、点線のワイヤー、入力中のキャレット、右下の進み具合の表示（例: 「Design wireframing…」）で表現する。

### 5.4 キャンバスの並べ方（Claude の判断。本人の確認待ち）

- 普段はフレームが**縦に積まれていて**、普通にスクロールして読める。
- Z キー（スマホではピンチ）で**ズームアウト**すると、トップのフレームと下層ページのフレームがすべて 2D に並んだキャンバス全体が見える。フレームをクリックすると、そこへズームインする。
- 縦に積むだけの案は、キャンバスらしさが見た目だけになる。全部を 2D に散らす案は、スマホ・アクセシビリティ・実装が重い。この案はその中間で、読みやすさを守りつつ「実はキャンバスだった」という驚きを足せる。
- Figma では、Top — Desktop に縦積みの完成形を置き、Prototype ページにズームアウトした俯瞰画面を1枚加える。

## 6. Figma ファイルの中身

新しい Figma Design ファイルを1つ作る。ページの分け方は次のとおり。

1. **Cover**: ファイルの表紙。
2. **Foundations**: 変数（色・文字・余白・角丸）の一覧と、文字スタイルの見本。
3. **Components**: カーソル（役割ごとのバリアント、通常と移動中）、フレーム（完成・枠だけ・ワイヤー）、選択枠、進み具合の表示、ナビゲーション、フッター、Works の年表の行（作品・経歴の2種）、Press の行、SNS リンク、ボタン、タグ。
4. **Top — Desktop**: 幅 1440 のトップページの完成形。
5. **Top — Mobile**: 幅 390 の完成形。
6. **Build sequence**: Hello フレームの組み立て（空 → 枠 → ワイヤー → 入力中 → 完成 → カーソルが集まる）を、Motion のタイムラインで動かしたもの。About me 以降のフレームも、それぞれ短いタイムライン（ワイヤー → 完成）を持つ。
7. **Sub pages**: About me、Works 一覧、作品の詳細、Press（デスクトップ）。
8. **Prototype**: Build sequence のアニメーションと完成画面をつなぎ、開いた直後に自動で組み上がるようにする。

変数はライトとダークの2モードを持つ。名前は `packages/tokens` の `--ut-*` に対応させる（例: `color/bg` → `--ut-color-bg`）。

### 6.1 補足（実装前の確認で決めたこと）

- **置き場所**: Figma のチーム「ut42tech」（Education プラン）に作る。このプランは変数のモードを複数持てるので、ライト／ダークを1つのコレクションの2モードにできる。
- **組み立ての動きの再現**（Claude の判断）: 組み立てそのもの（カーソルの移動、枠を描く、文字の打ち込み、要素が現れる）は Motion のタイムラインで本物の動きとして作る。ただし Motion もプロトタイプも、スクロール位置をきっかけに再生を始めることはできない。
  - 開いた直後の Hello の組み立ては、画面を開くと自動で再生する。
  - About me 以降は、↓キーまたはクリックで次のセクションのタイムラインへ進める。スクロールと連動した本物の手触りは実装で作り、速さやタイミングの最終判断も実装を触ってから行う。
  - Esc で完成形へ飛べるようにする。「再生し直す」はボタンにする。
- **スマホ**（Claude の判断）: スマホでも Hello だけは組み上がる。ただし短くして、カーソルは名札付きの2〜3個にする。指で触る端末には訪問者のカーソルがないので、「you」とカーソルが集まる演出は省く。Esc の代わりに、画面に「スキップ」ボタンを常に出す。About me 以降のフレームは、組み立てずにふわっと表示するだけにする。Build sequence ページにはスマホ版の Hello の3コマ（空 → 入力中 → 完成）も加える。
- **書体**（本人が決定）: 和文・欧文とも **LINE Seed JP** を使う。`--ut-font-sans` に入れる。
- **`--ut-color-accent`**（Claude の判断）: 残す。選択枠の青に使い、リンク・フォーカスリング・主ボタンにも同じ色を使う。鮮やかな色を名札と 3D に限るという方針の例外は、この1色だけにする。選択枠は「デザインツールの手触り」の中心なので、アクセント色と兼ねさせる。

### 6.2 進め方（本人の指定）

デザインはまだ固まっていないので、**2段階**で作る。いきなり細部まで作り込まない。

1. **方向性の確認**: 最小限の変数と、トップページの大まかな画面（PC とスマホ）、Hello の組み立ての動きだけを作る。部品化、下層ページ、プロトタイプのつなぎ込みはしない。本人が見て、方向性を決める。
2. **作り込み**: 方向性が決まってから、変数の整備、部品、全画面、組み立ての動き、プロトタイプを作る。この段階の手順は、1 の結果を踏まえて改めて計画する。

## 7. 実装者に任せること

- 具体的な色の値。グレーの段階、文字色、カーソル4色（Design / Frontend / 3D / you）の色相。ライトとダークの両方でコントラストが足りること（WCAG AA）は守る。
- 名札や進み具合の表示に使う等幅書体（`--ut-font-mono`）の選択。LINE Seed JP と並べて違和感がなく、Web フォントとして配信できるものにすること。
- 余白、文字サイズの段階、角丸の値。
- 仮の文章の中身。ただし名前・モットー・タグ・所属・SNS は `packages/profile` の実データを使う。
- プロトタイプのタイミングとイージング。
