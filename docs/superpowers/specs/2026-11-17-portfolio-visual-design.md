# ポートフォリオ 見た目（ビジュアル）設計書

- 日付: 2026-11-17
- 対象: `apps/web`（ut42tech.com）の見た目と動き
- 範囲: Figma の変数・部品・主要画面を、本番の見た目に仕上げるところまで。あわせて、動きの値を数値で決める。コードでの実装は別の計画で扱う。
- 前提: 画面の構造は [`2026-11-16-portfolio-wireframe-design.md`](2026-11-16-portfolio-wireframe-design.md) で確定している。本書はその上に見た目を載せる。

## 1. 目的と背景

第一印象で、**歓迎されている感じ**と「これからワクワクするものが見られる」期待感を出す。本人の細部へのこだわりは、**言葉ではなく見た目と手触りで**伝える。派手さよりも、自然さと気持ちよさを優先する（構造の設計書 3 章の原則と同じ）。

登場演出、Hello のあいさつ、吸い付くポインター、すりガラスの素材は、使い捨ての試作で手触りを確かめた。本人の評価は「めちゃくちゃ UX いい」。本書の動きの数値は、その試作の値を書き写したもの。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール

- Figma の変数（ライト／ダーク）が本番の値になっていて、`packages/tokens` の `--ut-*` にそのまま移せる。
- 主要な画面が、スマホとパソコンで本番の見た目になっている。
- 動き（登場演出、あいさつ、ポインター、押したときの反応）が数値で決まっていて、実装者が迷わず再現できる。

### 非ゴール（今回はやらない）

- Hello の 3D と AI エージェント。エージェントを作るときに一緒に作る（本人の決定）。それまでは、タイポグラフィのあいさつで代える。
- コードでの実装と、`packages/tokens` の値の差し替え。
- 実際の作品写真・文章の用意。仮の画像と文章でよい。

### アンチゴール（できても失敗とみなすもの）

- UI に色が付いて、**作品の写真やサムネイルが目立たなくなる**こと。
- 演出のせいで**待たされる**と感じること。
- 文字が背景に溶けて**読めない**こと。WCAG AA を下回るコントラストは不可。
- 既存のサイトやテンプレートの**模倣に見える**こと。OS の部品を描き写すこと。

## 3. 決まったこと（本人と合意済み）

- **全体はモノトーン。アクセントの色は持たない。** 色は作品のアイコン・サムネイル・写真に集中させる。
- **書体は LINE Seed JP。** 等幅は Geist Mono（日本語の字を含む箇所は LINE Seed JP）。
- **Hello はタイポグラフィのあいさつ**: 大きな「Welcome.」と、小さな「to ut42tech」。
- **登場演出**: 幕の上に「Takuya Uehara」を小さめに出してから、幕が上がる。
  - 本名は About の中だけ、という構造の設計書の決まりは、この演出についてだけ例外にする（本人の決定）。
- **パソコンのポインター**: iPad のようにボタンへ吸い付く。OSS の [ipad-cursor](https://github.com/CatsJuice/ipad-cursor)（MIT）を使う。
- **浮かせるのはナビゲーションバーだけ**（本人の決定）。黒い不透明な面にし、今いる項目を少し明るい黒で示す。ダークではその逆（白い面に、少し暗い白）。すりガラスは使わない。試作ではすりガラスを使ったが、アクセシビリティ（文字の読みやすさ）と統一感を優先した。ほかの部品（表示の切り替え、戻る、Works のサイドバー）は浮かせず、ページと同じ平面に置く。
- **シート**は文字やカードを読む場所なので、`color/surface` の不透明な面にする（Claude の判断）。
- **ナビゲーションバーはスマホとパソコンで同じ部品**（本人の決定）。項目は About / Works / Press の3つだけ（ホームは置かない）。スマホでは下、パソコンでは上の中央に浮かせる。Hello にいるときは、どの項目も選ばれていない状態になる。中身はバーの下を通ってスクロールする。
- **ハンドル（@ut42tech）はボタンの見た目にしない**（本人の決定）。浮かせず、左上に文字だけで置く。押すと Hello に戻る（本人が「ホームに戻る機能は残してもよい」とした。Claude の判断で、見た目は文字のまま、押せるようにだけする）。スマホではシートを下げても Hello に戻れる。
- **アイコンを使うべき所ではアイコンを使う**（本人の決定）。SNS のボタンはブランドのアイコン付き、Skills は言語とフレームワークのアイコンだけを並べる。
- **連絡の使い分けを書く**（本人の決定）。気軽な連絡は SNS へ、仕事の依頼などの正式な連絡はメールへ、と About の連絡先に書く。SNS は X、GitHub、LinkedIn、Qiita、Zenn、note、YouTube、Wantedly の8つ。
- **「研究について」のリンクは今回は載せない**（本人の決定。研究のサイトの公開まで時間がかかるため）。
- **About のプロフィール画像は大きめにする**（本人の決定）。スマホ 96px、パソコン 144px。

## 3.1 細部の決め（実装前の確認で Claude が決めたこと）

- **Hello の画面**: `bg` の上に「Welcome.」と「to ut42tech」だけを置く。3D の領域は今は取らない。ただし、将来のエージェントの入力欄のために、スマホではタブバーの上に余白を残す（構造の設計書 10 章）。シートの上端から覗くのは、Hello の地と「Welcome.」の上端。
- **ライト／ダークの切り替え**: OS の設定に従い、手動でも切り替えられる（今のコードの仕組みを引き継ぐ）。切り替えボタンは、自動／ライト／ダークを押すたびに順に切り替えるボタン1つにする。見た目はアイコンだけ（20px、`color/fg`。面も影も付けない。本人の決定）。押せる範囲は 44px 四方。パソコンではヘッダーの右端、スマホではすべての画面の右上に置き、アイコンの右端を横の余白（7 章）にそろえる。どの画面からでも同じ場所で切り替えられる（本人の指摘を受けて、About の一番下に置く案から変えた）。
- **アイコン**: タブバーとヘッダーの切り替えは、試作のとおり文字だけにする。
  - 操作のアイコンは [Tabler Icons](https://tabler.io/icons) 3.52.0（MIT）から選び、線の太さは 1.75 にそろえる（本人の決定、2026-11-17。最初は Lucide だった）。
    - 戻る `chevron-left`、閉じる `x`、外部へ開く `arrow-up-right`、並び替え `arrows-sort`、メール `mail`、コピー `copy`。
    - 表示の切り替えは、自動 `device-desktop`、ライト `sun`、ダーク `moon`。
    - 外部のサイトへ移るリンクには「↗」を付ける。
  - ブランドのアイコン（SNS、Skills、Press の媒体）は、すべて [Simple Icons](https://simpleicons.org) 16.38.0（CC0）から選ぶ（本人の決定）。Tabler にもブランドはあるが、Qiita・Zenn・note・Wantedly・Speaker Deck が無いため、塗りの形で揃えられる Simple Icons にまとめる。ブランドの色は使わず、`color/fg`（フォールバックの中では `color/muted`）の1色にする。LinkedIn は今の版から外されているため、最後に含まれていた 11.0.0 を別名の依存として読み込む。
  - **コードにアイコンの形を書かない**（本人の決定）。SVG もパスも、すべてパッケージから読み込む。
  - OS のアイコン（SF Symbols など）は使わない。
- **並び替え**: メニューは出さず、押すたびに「新しい順／古い順」が入れ替わる1つのボタンにする（試作のとおり）。ラベルは今の並び順を表す。

## 3.2 スマホとパソコンの対応（Claude の判断）

同じ規則で作り、違いは画面の大きさと入力の違いから出るものだけにする。

**共通の規則**

- **形**: 押して操作する部品（ボタン、切り替え、並び替え、SNS のボタン、戻る、表示の切り替え）は、すべて両端まで丸いカプセルにする。表示の切り替えだけは例外で、アイコンだけにする。中身の入れ物（カード 16、横長カード・Skills のタイル・メール欄・詳細の画像 12〜16）は角丸の四角にする。
- **今いる場所**: 明るい面の上では `fg` で塗った面に `bg` の文字。ナビゲーションバーの上では `bar-active`。
- **浮き方**: 浮くのはナビゲーションバーだけ（影 `shadow/float`）。シートは下から出てくるので、上向きの薄い影にする。それ以外は影を付けない。
- **画像の比率**: 作品の画像は、一覧のカードも詳細も 16:10 にそろえる。一覧から詳細へ移るとき、同じ画像がそのまま大きくなるようにつなげられる（動きのつながり）。
- **安全な領域**: 7 章の余白の内側に、文字と押せる部品を置く。
- **見出し**: 1画面に `Title L` の見出しを1つ。パソコンでは、どのページもヘッダーの下 28px（上から 104px）にそろえる。
- **文字のはみ出し**: カードと横長カードの題名は最大2行。日付・媒体名・説明は1行で、溢れたら「…」で切る。カードの高さは題名の行数によらず同じ。
- **画像がないとき**: 媒体のアイコンがあるもの（Press の Qiita、Speaker Deck など）はそのアイコン、ないものは頭文字を `placeholder` の面に出す。

**違い**

| 場所 | スマホ | パソコン |
| --- | --- | --- |
| ナビゲーションバー | 同じ部品（高さ 48）を下の中央に浮かせる。下端は画面の下の安全な領域から 8px 上 | 同じ部品を上の中央に浮かせる |
| ハンドル | 左上の文字（状態バーの下の 44px の段） | 左上の文字 |
| 表示の切り替え | 右上のアイコン（ハンドルと同じ段） | ヘッダー右端のアイコン |
| プロフィール画像 | 96px | 144px |
| ページ | Hello の上に重なるシート | `bg` の上に直接 |
| Works の分類 | シートの見出しの下の切り替え（カプセル） | 左のサイドバー。画面の上下の中央に置き、スクロールしても動かない（`position: sticky`。本人の決定）。見出しは選んだ分類名（Apps など）。サイドバーは `surface` の面に `border` の線のカード（角丸 16、内側の余白 4、影なし。本人の決定）。中の項目は高さ 44・角丸 12 で、カードの角丸と同心になる。サイドバーには見出しを付けない（上のナビゲーションで Works が選ばれていて、重ねて書くと冗長なため） |
| 一覧 | カード2列、横長カード1列 | カード3列（264 幅、間 24）、横長カード1列。中身の幅 840。Works ではサイドバーの右端から画面の右端までの中央、Press では画面の中央に置く。カードの大きさはどのページでも同じ |
| 横長カード | 高さ 100、画像 96 幅 | 高さ 100、画像 160 幅 |
| Skills | 48px のタイルを折り返し（6個ずつ） | 48px のタイルを1行 |
| SNS | 2列×4段のボタン（幅 171） | 4列×2段のボタン（幅 174） |
| Apps の詳細 | Works のシートの上に重なる2枚目のシート（タブバーより手前）。取っ手と右上の閉じる（×、32px の `fill` の丸）、16:10 の画像（350×219、角丸 16）、題名・説明・ボタン・Stack を縦に並べる。下のシートは左右 12px 狭まり、上端が 10px だけ見える | 戻る（`fill` のカプセル）の下に、16:10 の画像（720×450、読む幅）、その下に題名・説明・ボタン・Stack を縦に並べる。説明が長くても読みやすいよう、本文は読む幅 720 の1列 |

## 4. アプローチ

| 案 | 内容 | 判断 |
| --- | --- | --- |
| **1. 静止した見た目は Figma、動きは試作の値を設計書に書く** | 変数・部品・主要画面を Figma で仕上げる。動きは試作の数値を本書に書く。 | **採用（本人が選択）**。静止した値は Figma の変数から `packages/tokens` に移せる。動きは触って確かめた値をそのまま渡せる。 |
| 2. すべて Figma で仕上げる | 動きも Figma の Motion で作り込む。 | 不採用。吸い付くポインターや、文字がポインターに寄る動きは Figma で再現できず、手間に対して得るものが少ない。 |
| 3. Figma を飛ばしてコードで仕上げる | 試作の延長で、本番のコードに直接作り込む。 | 不採用。トークンを Figma と共有する流れが活きない。 |

## 5. 色（Claude の提案。モノトーンの範囲で決めた値）

Figma のコレクション `ut42tech`（モード Light / Dark）を、次の値に作り直す。キャンバス案の名残であるカーソル4色（`color/cursor/*`）と `color/on-cursor`、`color/grid-dot` は消す。

| Figma 変数 | `--ut-*` | Light | Dark | 役割 |
| --- | --- | --- | --- | --- |
| `color/bg` | `--ut-color-bg` | `#F4F4F3` | `#111112` | ページの地 |
| `color/surface` | `--ut-color-surface` | `#FFFFFF` | `#1C1C1E` | カード・シートの面 |
| `color/fg` | `--ut-color-fg` | `#141414` | `#F2F2F2` | 文字・選択中の面 |
| `color/muted` | `--ut-color-muted` | `#6B6B6B` | `#8D8D92` | 補足の文字 |
| `color/border` | `--ut-color-border` | `#E3E3E3` | `#2C2C2E` | 罫線・カードの枠 |
| `color/fill` | `--ut-color-fill` | `#000000` 7% | `#FFFFFF` 10% | 押せる面の地・ホバー |
| `color/placeholder` | `--ut-color-placeholder` | `#ECECEB` | `#232325` | 画像がないときのフォールバックの面 |
| `color/bar` | `--ut-color-bar` | `#141414` | `#F2F2F2` | ナビゲーションバーの面 |
| `color/bar-active` | `--ut-color-bar-active` | `#363638` | `#D4D4D4` | ナビゲーションバーの今いる項目 |
| `color/on-bar` | `--ut-color-on-bar` | `#F4F4F3` | `#111112` | バーの上の今いる項目の文字・アイコン |
| `color/on-bar-muted` | `--ut-color-on-bar-muted` | `#A3A3A3` | `#6B6B6B` | バーの上のほかの項目の文字・アイコン |
| `color/scrim` | `--ut-color-scrim` | `#000000` 25% | `#000000` 50% | 詳細のシートの後ろを暗くする層 |
| `color/curtain` | `--ut-color-curtain` | `#141414` | `#F2F2F2` | 登場演出の幕（前景色と同じ） |
| `color/on-curtain` | `--ut-color-on-curtain` | `#F4F4F3` | `#111112` | 幕の上の名前 |

- **アクセントの代わり**: 今いる場所（タブ、分類ボタン、切り替え）は `fg` で塗った面に `bg` の文字で示す。リンクには下線を付ける。キーボード操作のフォーカスの枠は、`fg` の 2px の線を 2px 離して出す。
- `--ut-color-accent` はコードの仕組みに残っているので、`fg` と同じ値にする（名前だけ残す）。
- **コントラスト**: `muted` は試作の値（`#8A8A8A`、地に対して 3.14）が AA に届かないため、`#6B6B6B`（地 4.84、カード 5.33）に上げた。Dark の `muted` は地 5.71、カード 5.15。`fg` と地は両モードとも 16 以上。タブバーは、今いる項目の文字と面が Light 10.96 / Dark 12.73、ほかの項目の文字と面が Light 7.3 / Dark 4.76。

## 6. 書体（Claude の提案）

| `Title M` | LINE Seed JP | 28 | ExtraBold | 130% | -1% | About の本名（パソコン）、フォールバックの頭文字 |
| `Headline` | LINE Seed JP | 16 | Bold | 145% | 0 | Career の横長カードの題名（パソコン） |
| `Card Title` | LINE Seed JP | 14 | Bold | 20px 固定 | 0 | カードの題名（最大2行） |
| `Body` | LINE Seed JP | 15 | Regular | 180% | 0 | 本文 |
| `Callout` | LINE Seed JP | 13 | Regular / Bold | 160% | 0 | ボタン、タブ、説明 |
| `Caption` | LINE Seed JP | 12 | Regular | 150% | 0 | 件数、補足 |

- Geist Mono には日本語の字がない。日本語を含む補足（例: 件数の「件」）は `Caption` を使う。

## 7. 形・余白・影・トークン（Claude の提案）

- **角丸**: カード・詳細の画像 16、横長カード・タイル・メール欄・サイドバーの項目 12、シート上端 28、押して操作する部品はすべて 999（カプセル。3.2 の規則）。
- **余白**: 4 の倍数（4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 56）。パソコンの中身の最大幅は 840（一覧）と 720（About、Apps の詳細）。Works の中身は、サイドバーの右端（左から 248px）から画面の右端までの中央に置く。
- **安全な領域**（本人の指摘を受けて決めた）:
  - スマホ: 上は状態バーの 47px、下はホームインジケーターの 34px を空ける（Figma のフレームでは赤い帯のガイドで示す）。実装では `viewport-fit=cover` にして、`env(safe-area-inset-top / bottom / left / right)` を足す。値が 0 の端末でも、上下に最低 12px は空ける。
  - スマホの横の余白は 20px。横向きのときは `env(safe-area-inset-left / right)` を足す。
  - 状態バーの下に 44px の段を取り、ハンドルと表示の切り替え（詳細では戻る）を置く。シートはその下（上から 99px）から始める。画像だけは状態バーの下まで広げてよいが、今の設計では使っていない。
  - パソコンの横の余白は 32px（ハンドル、サイドバー、表示の切り替えのアイコンの右端）。
- **境界**: 影は使わず、`color/border` の 1px の線で区切る。ナビゲーションバーとシートにだけ影を付ける（8 章）。

色以外の値も、トークンとして名前を決めておく。Figma では数値の変数（コレクション `ut42tech/size`、モードなし）にし、コードでは `--ut-*` にする。イージングと時間は Figma に変数の仕組みがないので、コードのトークンだけにする。

| 種類 | Figma 変数 | `--ut-*` | 値 |
| --- | --- | --- | --- |
| 角丸 | `radius/card`、`radius/row`、`radius/control`、`radius/segment`、`radius/sheet`、`radius/full` | `--ut-radius-card` など同名 | 16 / 12 / 999 / 999 / 28 / 999（`control` と `segment` は `full` の別名） |
| 余白 | `space/1`〜`space/14` | `--ut-space-1` など | 4 の倍数（4〜56） |
| 中身の幅 | `width/content`、`width/reading` | `--ut-width-content`、`--ut-width-reading` | 840 / 720 |
| イージング | — | `--ut-ease-out`、`--ut-ease-rise`、`--ut-ease-curtain`、`--ut-ease-in-out` | 9 章のとおり |
| 時間 | — | `--ut-duration-fast`、`--ut-duration-base`、`--ut-duration-slow` | 180 / 250 / 600ms |
| 影 | 効果のスタイル `shadow/float`、`shadow/sheet` | `--ut-shadow-float`、`--ut-shadow-sheet` | `0 8px 24px` 黒 18% / `0 -8px 30px` 黒 8% |

既存の `--ut-radius`（1つだけ）は、`--ut-radius-row`（12）の別名として残す。

### 7.1 整列の規則（仕上げの点検で決めた。Claude の判断）

- **4px の格子**: 余白・間隔・高さは 4 の倍数にする。例外は、切り替えの項目どうしの間 2px と、スマホの下の安全な領域 34px だけ。
- **部品の高さ**: 並び替え・戻る 36／ボタン（Demo など）・切り替え 40（中の項目 32）／SNS のボタン・サイドバーの項目・表示の切り替えの押せる範囲 44／ナビゲーションバー（中の項目 40）・メール欄 48。同じ並びに置く部品は同じ高さにする（Demo と GitHub など）。
- **枠線は内側**: 枠線で部品の大きさが変わらないようにする（`box-sizing: border-box`、Figma では線を内側に、レイアウトに含めない）。
- **アイコンの大きさ**: 13px の文字と並ぶ操作は 14、単独の操作（閉じる・コピー・メール）は 16、SNS のブランドは 18、表示の切り替えは 20、Skills のタイルの中は 22、フォールバックの媒体アイコンは 32。
- **アイコンと文字の間**: 操作の中は 8、メール欄は 12。
- **角丸は同心にする**: 入れ物の角丸 ＝ 中の部品の角丸 ＋ 間の余白。サイドバー 16 ＝ 項目 12 ＋ 4。カプセルの中にカプセル（ナビゲーションバー、切り替え）は余白 4。
- **見切れ**: 文字を入れる枠は中身を切り取らない（`overflow: visible`）。切り取るのは、画像の角丸と、シート・カードの外形だけ。

## 8. 浮かせる部品と影

- **面**: `color/bar` の不透明な面。透けさせない。試作で使ったすりガラスはやめた（3 章）。`color/glass*` の変数は消した。
- **影**: `shadow/float`（`0 8px 24px` 黒 18%）。ナビゲーションバーだけに付ける。
- **シート**: `color/surface` の面に、上向きの `0 -8px 30px` 黒 8%（効果のスタイル `shadow/sheet`）。
- ダークでは影がほとんど見えないが、`bar` が白い面になるので浮いて見える。
- 表示の切り替え（アイコンだけ）、戻る（`fill` のカプセル）、パソコンのサイドバー（カードと同じ面と線）は浮かせない。

## 9. 動き（試作で確かめた値）

共通の決まり:

- 動きの原則は、構造の設計書 3 章の4つ（すぐ反応する／動きがつながる／意図に応える／遊びを加える）。
- **イージング**:
  - `ease-out`: `cubic-bezier(.2, .8, .2, 1)`。ほとんどの動き。
  - `ease-rise`: `cubic-bezier(.2, 1, .3, 1)`。文字が上がる。少しだけ行き過ぎて戻る。
  - `ease-curtain`: `cubic-bezier(.76, 0, .24, 1)`。幕。
  - `ease-in-out`: `cubic-bezier(.7, 0, .3, 1)`。幕の上の名前が抜ける。
- **ばね**: 文字がポインターへ寄る動きは、ばね（硬さ 160、減衰 20、1 秒あたり）で動かす。
- 「視差効果を減らす」（`prefers-reduced-motion`）では、下で「減らす設定」と書いたとおりに動きを止めるか、置き換える。

### 9.1 登場演出

| 時刻（ms） | 動き |
| --- | --- |
| 0 | 画面全体を `color/curtain` の幕が覆っている（5本の縦の帯） |
| 80 | 「Takuya Uehara」が下からせり上がる（600ms、`ease-out`、文字の高さ分の窓から現れる） |
| 780 | 名前が上へ 24px 抜けながら消える（500ms、`ease-in-out`。不透明度は 350ms） |
| 780 | 5本の帯が、左から 60ms ずつ遅れて上へ抜ける（各 820ms、`ease-curtain`） |
| 1060 | 「Welcome.」が1文字ずつ下から上がる（各 900ms、`ease-rise`、1文字 45ms ずつ遅らせる。0.35em 下から） |
| 1660 | 「to ut42tech」がふわっと現れる（600ms） |
| 1930 | 幕を取り除く |

- **見せるのは1回の訪問で最初だけ**（タブを閉じるまで記憶する）。2回目以降のページの読み込みでは出さない。
- **いつでも飛ばせる**: キー入力、ホイール、タップで、その場で完成した状態にする。
- **待たせない**: 書体の読み込みを最大 1.5 秒まで待つ。それを超えたら、読み込みを待たずに幕を上げる。
- **減らす設定**: 幕は 400ms でふわっと消すだけ。あいさつは最初から出しておく。
- **Hello 以外のページから入ったとき**（共有されたリンクで `/works/apps/<slug>` などを直接開いた場合。Claude の判断）: 幕と名前は同じように出し、幕が上がった先はそのページにする。「Welcome.」の演出は Hello でだけ起こす。

### 9.2 Hello のあいさつ

- 「Welcome.」の各文字は、ポインターとの距離が 420px 以内のときに、ポインターの方へ寄る。
  - 寄る量は横に最大 14px、縦に最大 10px で、近いほど大きい。
  - ばねで動き、ポインターが 2.5 秒止まると元の位置に戻る。
- 文字を押すと、全体が上に軽く弾む（各文字に上向きの初速 260〜320px/s を与え、同じばねで戻す）。
- 読み上げ用に、文字をまとめた見出し（`aria-label="Welcome."`）を置く。1文字ずつの要素は読み上げない。
- **減らす設定**: 寄る動きも弾む動きもしない。

### 9.3 パソコンのポインター（ipad-cursor 0.5.2）

- マウスなど細かく指せる端末（`pointer: fine`）でだけ使う。タッチ端末では使わない。
- 押せる要素には `data-cursor="block"` を付ける。
- 設定:

```js
initCursor({
  normalStyle: { background: 'rgba(127,127,127,.28)', backdropBlur: '0px' },
  blockStyle: { background: 'rgba(127,127,127,.14)', radius: 'auto', durationPosition: '0.2s' },
  textStyle: { background: 'rgba(127,127,127,.5)' },
  enableAutoTextCursor: false,
  enableMouseDownEffect: true,
  enableLighting: true,
})
```

- 画面の中身が入れ替わったら（シートの切り替え、Works の分類の切り替えなど）、`updateCursor()` を呼ぶ。Vue の部品では `ipad-cursor/vue` の `useCursor` を使う。
- ライブラリの最後のリリースは 2023-07。不具合が出たら、手元に取り込んで（フォークして）直す前提で使う。
- **減らす設定**: ライブラリを読み込まず、OS の標準のポインターにする。

### 9.4 画面の移り変わり（Claude の提案。試作していないので、実装時に触って調整する）

- **シートがせり上がる**: ばね（硬さ 380、減衰 34）で、行き過ぎはほとんどない。閉じるときも同じばねで、指を離したときの速さを引き継ぐ。
- **払って閉じる判断**: 指を離した位置に、慣性で進む距離を足して判断する（1ms あたりの減衰率 0.998）。予測した位置がシートの高さの 1/3 を越えたら閉じる。
- **カードから Apps の詳細へ**: サムネイルが詳細の画像の位置へ移る動きは、ブラウザの画面遷移の機能（View Transitions）で、360ms・`ease-out` にする。スマホでは同時に、下の Works のシートが 250ms で奥へ下がり（左右を 12px 狭め、上端を 10px 上へ）、全体を `scrim` で暗くし、詳細のシートが上と同じばねで上がる。払って閉じるときは、指の速さのまま元のカードへ戻す。画面の外へ投げる遊びは、予測した位置が画面の外になったときだけ起こす。
- **切り替え・分類ボタンで中身を入れ替える**: 古い中身が 120ms で消え、新しい中身が 8px 下から 200ms で現れる（`ease-out`）。
- **減らす設定**: どれも 150ms のふわっとした切り替えにする。

### 9.5 押したときの反応

- スマホのタブ・ボタン: 押している間、`scale(.92)` に沈む（180ms、`ease-out`）。
- 選択中の表示の切り替え（タブ・分類ボタン・切り替え）: 背景色と文字色を 250ms で変える。
