# ポートフォリオの「動き」と Nuxt への移行 設計書

- 日付: 2026-11-18
- 対象: `apps/web`（ut42tech.com）
- 前提の設計書: [構造](2026-11-16-portfolio-wireframe-design.md)、[見た目](2026-11-17-portfolio-visual-design.md)。本書と食い違うところは本書を優先する（12 章に一覧）。
- 試作: Nuxt 4 + Motion for Vue の使い捨ての試作で、シートと詳細の動きを本人が iPhone と Chrome で触って確かめた（2026-11-18）。本書の数値はその試作で詰めた値。試作のコードはリポジトリに入れない。

## 1. 目的と理由

ポートフォリオを、読むサイトから**触って気持ちのいいアプリ**にする。本人の技術的なアピールを兼ねているので、ネイティブアプリ並みの滑らかさに妥協しない（本人の言葉: 「中途半端な実装をして UX を下げるなら、それは良くない」）。

今のサイト（Astro の静的 MPA）は、タブを押すたびにページを丸ごと読み直す。その間は指の速さを次の画面へ渡せず、動きの途中で次の操作も受け付けられない。設計原則（構造の設計書 3 章: すぐ反応する／動きがつながる／意図に応える／遊びを加える）を満たすには、ページを移っても画面の土台（Hello、シート、ナビ）が生き続ける作りが要る。そこで `apps/web` を Nuxt に移し、動きを Motion for Vue で作る。

Vue を選ぶのは本人の意図でもある。React が主流の中で Vue で作り込んだサイトは、それ自体が目に留まる（本人の判断）。

## 2. 目標・目標外・失敗とみなすこと

**目標**

- タブで開くシート、シートを払って Hello へ戻る、タブの切り替え、Apps の詳細の開閉が、指に遅れずに付いてきて、離したときの勢いを引き継ぎ、動きの途中でも次の操作を受け付ける。
- 登場演出、あいさつ、ポインター、押したときの反応を、見た目の設計書 9 章の値で入れる。
- 今のサイトにあるもの（13 章）を、すべて引き継ぐ。
- コードがきれいであること（本人の要望）。動きの数値と判断はフレームワークに依存しない形で持ち、Vue は画面の層だけにする（6 章）。

**目標外**

- AI エージェント（構造の設計書 10 章）。ただし今回の作りがそれを妨げないようにする。
- 英語の公開、`ut42tech.com` の接続（どちらも本人の判断で後回し）。
- 中身（本人が書く文章）。

**失敗とみなすこと（動いていても）**

- 動きが途中でガクンと飛ぶ、行き過ぎて揺れる、最後にパキッと切り替わる。試作で本人が指摘したのは、まさにこの3つだった。
- 動きが二重になる（Safari の端スワイプで戻ったときなど）。
- 指を離したあと、勢いを無視して決まった速さで動く。
- JavaScript が動かないと中身が読めない、検索エンジンに中身が見えない。

## 3. 前提と制約

- 公開リポジトリ。参考にしたサイトの名前を書かない。旧サイトの `private/` は入れない。
- SVG、文言、色を部品に直接書かない（今のテストの決まりを引き継ぐ）。
- 値は `packages/tokens` から読む。
- スマホとパソコンの境目は 1024px。同じ HTML を CSS で出し分ける。
- 公開は Vercel の `hp-v2`。静的に書き出す。
- 対応ブラウザ: 最新の Safari（iOS と macOS）、Chrome、Firefox。Firefox にも同じ動きを出す（ブラウザの画面遷移の機能に頼らないので可能）。
- 「視差効果を減らす」設定を尊重する（8.9）。

## 6. コードの層（本人と合意）

Vue は「見た目の層」だけにして、それ以外はフレームワークに依存しない形で持つ。数年後に React のアプリを足しても、作り直すのは一番上の層だけで済むようにするため。

| 層           | 置き場                                                                 | 中身                                             |
| ------------ | ---------------------------------------------------------------------- | ------------------------------------------------ |
| 数値         | `packages/tokens`（CSS 変数に加えて、TS の定数を書き出す `motion.ts`） | ばね、イージング、時間、閉じる判断のしきい値     |
| 中身         | `packages/profile`、`apps/web/content`                                 | プロフィール、作品                               |
| 動きの仕組み | `apps/web/app/motion/`（素の TS。Vue を import しない）                | 指で引く処理、慣性の予測、閉じる判断、ポインター |
| 画面         | `apps/web/app/` の Vue の部品                                          | 上の層を組み合わせるだけ                         |

- 動きの仕組みは、ほかのアプリで要るようになってからパッケージに移す（今は `apps/web` の中に置く）。
- 純粋な計算（予測、判断）は単体テストを書く。

## 7. 画面の構造

ページを移っても、次の4つは作り直さずに生き続ける。

- **Hello の舞台**（「Welcome.」と「to ut42tech」。シートの裏に常にある）
- **シートの土台**（スマホ。About、Works、Press の中身を入れ替えて見せる1枚のシート）
- **ナビゲーションバー**
- **ヘッダー**（ハンドル、言語の切り替え、表示の切り替え）

URL は今のまま（13 章）。Apps の詳細は `/ja/works/apps/<slug>` で、Works の一覧の子のページにする。詳細を開いても一覧は残り、裏で奥へ下がる。

- どの URL も、書き出した HTML だけで読める状態にする。シートの開閉は URL から決まり、最初の描画から開いた状態で出す（動きは JavaScript が動いてから）。
- シートの中身を出す部品は、Nuxt の `useRoute()` ではなく、Vue Router の今の経路を直接読む。`useRoute()` はページの描画が終わるまで更新されないため、シートが自分で中身を保持していると、いつまでも切り替わらない（試作で起きた）。

## 8. 動き

### 8.1 共通のばねと判断

試作で詰めた値（本人が確かめた）。見た目の設計書 9 章の値を一部変えている。

| 値                   | 数値                                           | 備考                                                                                                                                                                          |
| -------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| シートのばね         | 硬さ 380、減衰 39                              | 減衰 39 はちょうど行き過ぎない強さ（2√380）。設計書の 34 では約 3px 行き過ぎて、止まり際に揺れて見えた                                                                        |
| 止まったとみなす基準 | 位置の差 0.0005、速さ 0.005/秒                 | シートの位置を 0（閉じた）〜1（開いた）の割合で扱うため。Motion の初期値（0.01、0.1/秒）だと、スマホで約 8px 手前で止まったことにされ、残りが一気に飛んだ（試作の「ガクン」） |
| 慣性の予測           | 1ms あたりの減衰率 0.998                       | 指を離した速さ（px/秒）から、止まる位置までの距離を `速さ / 1000 × 0.998 / (1 − 0.998)` で出す                                                                                |
| 閉じる判断           | 引いた距離 + 予測した距離 > シートの高さの 1/3 | 速く払えば少しの距離でも閉じる                                                                                                                                                |

- どの動きも、動いている途中で新しい目標が来たら、今の速さのまま向きを変える（Motion の値は速さを持っているので、新しい動きにそのまま渡す）。
- 指で引く間は、シートは指に直接付いてくる。開ききった位置より上へ引くと、引いた量の 0.15 倍だけ動く（ゴムのような抵抗）。
- 要素の大きさは、Motion の部品に付けた参照からではなく、その部品の実際の要素から測る。参照が部品そのものを指していて、高さが読めずに初期値が使われていた（試作の「サムネイルのずれ」の原因）。

### 8.2 タブでシートを開く・閉じる（スマホ）

- Hello からタブを押すと、シートが下からせり上がる（8.1 のばね）。
- 取っ手と見出しの部分（取っ手の段と、ページの大見出しの段。Works では分類の切り替えより上）を下へ引いて離すと、8.1 の判断で閉じるか戻るかを決める。閉じるときは離した速さを引き継いで下がり、Hello へ戻る。シートの中のスクロールとはぶつけない（構造の設計書 6.5 の 2）。
- 閉じる途中でタブを押すと、下がる勢いが残ったまま折り返して、押したタブの中身で上がり直す。

### 8.3 タブの切り替え（スマホ。本人の決定、2026-11-18）

- シートを開いたまま別のタブを押すと、**シートが一度下へしまわれ、見えない間に中身を入れ替え、また上がってくる**。
- 中身を入れ替えるのは、シートが 97% しまわれた時点（割合 0.03 以下）。そこからすぐ上がり始め、しまわれたときの勢いを引き継いで折り返すので、一続きの動きに見える。Chrome の計測で、しまうまで約 0.23 秒、上がりきるまで約 0.3 秒。
- 入れ替えたら、シートの中のスクロール位置を一番上に戻す。
- しまっている途中でさらに別のタブを押したら、入れ替え先だけを最後に押したタブに変える。
- 同じタブの中の移動（Works で詳細を開く、Works の分類を変えるなど）では、シートは動かない。Works の分類を変えたときは、シートの中の一覧だけを 8.6 と同じ動き（120ms で消え、8px 下から 200ms で現れる）で入れ替える（Claude の判断）。

これは構造の設計書 6.3 の「シートを閉じずに中身だけが入れ替わる」を置き換える。試作で中身だけを入れ替えたところ、本人が違和感を持った。

### 8.4 Apps の詳細（スマホ。本人の決定、2026-11-18）

- カードを押すと、**詳細は画像も含めたシート1枚として下から上がる**。カードのサムネイルはその場に残る。
- 同時に、裏の Works のシートが奥へ下がり（左右を 12px 狭め、上端を 10px 上へ）、全体が `scrim` で暗くなる。奥へ下がる量と暗さは、詳細の開き具合（0〜1）に合わせて動かす。
- 取っ手と、詳細の画像の部分を下へ引くと、8.1 の判断で閉じるか戻るかを決める。
- **画面に見える閉じるボタン（×）は置かない**。閉じ方は、下へ払う、ブラウザの「戻る」、Esc、Android の戻る操作。画面の読み上げを使う人のために、目に見えない「閉じる」ボタンを置く（Claude の判断）。
- 詳細は、ブラウザ標準の `<dialog>` をモーダルとして開いて作る（フォーカスを閉じ込める、裏を操作不能にする、Esc と戻る操作で閉じる、を標準に任せる）。動きは Motion で付ける。
- 見た目の設計書 9.4 の「サムネイルが詳細の画像の位置へ移る動き」と「画像を画面の外へ投げる遊び」は**やめる**。試作で画像だけが飛ぶ動きを触った本人が、シート1枚で出るほうが自然だと判断した。

### 8.5 閉じたときの履歴

- 詳細やシートを閉じるとき、一つ前の履歴が閉じた先（一覧、Hello）なら履歴を戻る。そうでなければ今の履歴を閉じた先に置き換える。閉じても履歴は増えず、ブラウザの「戻る」で閉じたものがまた開くことはない（今のサイトで直した決まりを引き継ぐ）。
- ブラウザの「戻る」で閉じたときも、同じ閉じる動きを見せる。
- **Safari の端スワイプで戻ったとき**は、Safari が自分の戻る動きを見せるので、こちらの動きは省いて結果だけを反映する。判定には `popstate` の `hasUAVisualTransition` を使う。試作で本人が iPhone の Safari で確かめ、動きが二重にならないことを確認した（2026-11-18）。

### 8.6 パソコン（Claude の判断）

パソコンにはシートがない（見た目の設計書 3.2）。

- タブ（上のナビ）を押すと、中身を入れ替える。古い中身が 120ms で消え、新しい中身が 8px 下から 200ms で現れる（見た目の設計書 9.4 の「中身を入れ替える」の値）。
- Apps の詳細は、今のとおり一覧の場所に置き換わる（「戻る」のカプセルで一覧へ戻る）。**カードのサムネイルが詳細の画像へ移り、ほかは入れ替わるように薄れる**（本人の決定、2026-11-18。スマホと違い、パソコンでは画像がつながるほうを選んだ）。ブラウザの画面遷移の機能（同じ文書の View Transitions）で作る。画像は 360ms・`ease-out`（見た目の設計書 9.4 の値）、ほかは 200ms で入れ替わる。戻るときは逆向き。ブラウザの「戻る」でも同じ動き。View Transitions に対応しないブラウザと「視差効果を減らす」設定では、動かさずに切り替える。
- Works の分類の切り替えも同じ動き。

### 8.6.1 選んでいる印（本人の決定、2026-11-18）

ナビゲーションバー、スマホの Works の分類（カプセル）、パソコンのサイドバーでは、選んでいる項目の面（印）が、**押した項目へ滑って移る**。見た目の設計書 9.5 の「背景色と文字色を 250ms で変える」を置き換える（文字色は 250ms で変えるまま）。

- 印は場所ごとに1つ。ばねで動かす（硬さ 500、減衰 45。小さな面なので、シートより速く、行き過ぎない）。
- Hello など、選んでいる項目がないときは印を出さない。
- 「視差効果を減らす」設定では滑らせず、その場で切り替える。

### 8.7 登場演出とあいさつ

見た目の設計書 9.1 と 9.2 のとおり（数値は変えない）。実装の決まり:

- **最初の描画の前に決める**: 登場演出を見せるかどうか（このタブで初めての読み込みか）を、`<head>` のインラインのスクリプトで決める。記憶には `sessionStorage` を使う。見せない読み込みでは、幕を一瞬でも描かない。
- 「Welcome.」の文字が寄る動きと弾む動きは、ばね（硬さ 160、減衰 20）を Motion で動かす。

### 8.8 ポインター（パソコン）

Motion の上に自分たちで書く（4 章）。素の TS のモジュールにし、Vue に依存させない。振る舞いは見た目の設計書 9.3 の設定から引き継ぐ。

- `pointer: fine` の端末でだけ動かす。タッチ端末では読み込まない。
- ふだんは小さな丸（`rgba(127,127,127,.28)` 相当の灰色。値はトークンに置く）。
- `data-cursor="block"` の要素に乗ると、その要素の形（位置、大きさ、角の丸み）に合わせて広がる（背景 `rgba(127,127,127,.14)` 相当、位置の移動は 0.2 秒）。
- 押している間は少し縮む。要素の上では、ポインターの位置に合わせて光が動く（設計書の「lighting」）。
- 画面の中身が入れ替わっても、自分で追いかける（要素の出入りを見張る。部品の側から更新を呼ばなくてよいようにする）。
- 色は `rgba()` で書かず、トークンから読む（ハードコード禁止のテストに合わせる）。

### 8.9 押したときの反応

見た目の設計書 9.5 のとおり。スマホのタブとボタンは押している間 `scale(.92)` に沈む（180ms、`ease-out`）。CSS で書く。

### 8.10 視差効果を減らす設定

- シート、詳細、タブの切り替え: 指で引く間は指に付いてくる（直接の操作なので）。離したあとや、押して開くときは、ばねを使わずに 150ms のふわっとした切り替えにする。
- 登場演出: 幕を 400ms でふわっと消すだけ。あいさつは最初から出しておく。
- 文字が寄る動き、弾む動き、ポインター: 動かさない（ポインターは OS の標準）。

## 9. 段階

1. **Nuxt への移行と画面の土台**: 13 章をすべて引き継いだうえで、7 章の構造と 8.1〜8.6、8.9、8.10（該当分）を入れる。ここまでで本番に出せる状態にする。Astro とその設定は `apps/web` から取り除き、README、引き継ぎ（`docs/handoff.md`）、基盤の設計書の表を新しい構成に合わせる。
2. **演出の仕上げ**: 8.7（登場演出、あいさつ）、8.8（ポインター）。

段階ごとに計画を分ける。

**動きの確かめ方**

- 純粋な計算（慣性の予測、閉じる判断、ばねの値）は単体テストで確かめる。
- 動きそのものは自動のテストにしない。段階ごとに、iPhone の Safari とパソコンの Chrome・Safari・Firefox で本人が触って確かめる。2 章の「失敗とみなすこと」に当たる動きがないことが合格の条件。

## 13. 移行で引き継ぐもの

今のサイトにあるものは、すべて引き継ぐ。

- **URL**: `/`（言語へ振り分け）、`/ja/`、`/ja/about`、`/ja/works/apps`・`career`・`awards`・`events`（`/ja/works` は Apps へ）、`/ja/works/apps/<slug>`、`/ja/press`、404。英語は辞書を持つが書き出さない（公開する言語の一覧で切り替える今の仕組み）。
- **検索エンジン向け**: canonical と hreflang（絶対 URL）、404 は `noindex` で canonical と hreflang を出さない、OGP（共通の画像 `packages/assets/og.png`、`twitter:card` は `summary_large_image`）。
- **表示の切り替え**: 最初の描画の前に `<head>` のインラインのスクリプトでテーマを決める。アイコンと読み上げ用の名前は、3つとも書き出して CSS で1つを見せる（読み込みが終わる前から正しい）。
- **言語の切り替え**: 公開している言語が2つ以上のときだけ出す。選んだ言語をクッキー `ut42tech-lang` に覚える。
- **見た目**: Figma とトークンのとおり。ヘッダーはパソコンでページの色を持つ。`scroll-padding-top` でフォーカスがヘッダーに隠れないようにする。外部へ移るカードには「↗」（SNS のボタンには付けない）。
- **Works**: 並べ替え（新しい順／古い順）、分類ごとの件数、パソコンのサイドバー。
- **About**: メールアドレスのコピー、SNS のボタン。
- **ハードコードの禁止**: SVG、文言、色を部品に直接書かないことを、テストで見張る（対象を Nuxt のフォルダに合わせる）。
- **アクセシビリティ**: 各ページに見出しは1つ、本文へ移るリンク、ナビの「今のページ」、名前のない操作がないこと。
- **JavaScript が動かないとき**: 中身はすべて読める。
